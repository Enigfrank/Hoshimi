# 导出诊断包

诊断包用于整理问题反馈资料，由本机生成并下载，不自动上传，也不受可选使用统计开关影响。

**CrashSightLog 日志需要在游戏客户端完全退出后才能获取。请先退出游戏客户端，再使用诊断包收集功能；收集时保持服务端运行。**

## 操作步骤

1. 复现问题并完全退出游戏客户端后，保持服务端运行，在服务器电脑浏览器打开 `http://127.0.0.1:8080/gm/`。修改过 HTTP 端口时使用实际端口。
2. 打开左侧的 **诊断包**，填写开始和结束时间。默认最近 24 小时，输入时间按浏览器所在电脑的本机时区解释。
3. 点击 **生成并预览**。检查收集提示，在文件下拉框逐项查看包内完整内容。
4. 点击 **下载已预览的 ZIP**，得到 `Hoshimi-diagnostics.zip`。检查后自行附到 Issue，并补充复现步骤与预期结果。

下载内容与预览一致，后续新增日志不会混入。预览保存在进程内，有效期 10 分钟；重新生成会替换上一份，停服也会使其失效。修改时间范围后需要重新生成。

如果在游戏客户端退出前已经生成过预览，请退出客户端后重新点击 **生成并预览**，再下载诊断包。

## 包含内容

| 文件或目录 | 内容 |
|---|---|
| `manifest.json` | 所选时间范围、收集限制、文件清单及缺失、跳过、截断提示 |
| `summary.json` | 服务端版本与编译时间、客户端版本名称、端口、资源模式等白名单配置摘要 |
| `protocol-fallback.json` | 生成预览时的协议兜底累计快照；不是所选时段内的命中次数 |
| `server-logs/` | 选定时段的服务端运行日志，包括轮转日志 |
| `crashsight-logs/` | 配置的游戏目录下 `CrashSightLog` 文件夹中的相关日志 |

CrashSight 日志目录从实际生效的游戏目录解析。例如，游戏目录为 `E:\AetherGazerLauncher\AetherGazer` 时，读取 `E:\AetherGazerLauncher\AetherGazer\CrashSightLog`。不会搜索整个磁盘，也不会修改游戏文件。

服务端日志默认来自 EXE 同级 `logs/`；使用 `--log-dir` 时收集实际日志目录。`--no-log` 不生成本次运行日志，已有历史日志仍可按时间选择。游戏日志目录不存在、为空或无法读取时会明确提示，其他资料仍可导出。

## 时间筛选与大小限制

- 能识别行首日期时间的日志按行筛选，异常堆栈等续行跟随上一条时间；没有时区的日志时间按服务器电脑本机时区解释。
- 整份日志没有可识别的行时间时，按文件修改时间选择整份日志，并明确标记。此类内容可能超出所选时段。
- 每个日志来源最多检查最近 64 个普通 `.log`、`.log.1` 至 `.log.3` 或 `.txt` 文件，不递归、不跟随目录或文件链接。
- 每个文件最多读取末尾 4 MiB，每类日志各保留 8 MiB 读取额度，两类合计最多读取 16 MiB；达到上限会提示，较早日志可能缺失。服务端日志不会占用 CrashSight 日志的额度。
- 兼容 UTF-8 及带 BOM 的 UTF-16；其他无法解码的字符用替换符显示，并给出提示。

## 日志内容与分享

只收集白名单配置摘要，不额外打包完整配置、存档、聊天文件、照片、证书、私钥文件、官服快照或 SDK 登录缓存。服务端与 CrashSight 日志均保留原文件名及筛选后的原始文字，不进行自动脱敏。

分享前请逐项检查预览；不希望公开的内容请在下载后自行删除，或改用手动提供片段。诊断包也不能替代问题发生位置、操作顺序和截图。

服务端无法启动、不能访问 GM 页面时，请按[问题上报指南](reporting.md)手动收集启动错误和对应的 CrashSight 日志。
