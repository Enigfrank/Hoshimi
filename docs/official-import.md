# 官服存档导入（实验功能）

`import-official` 可以复用本机官方 PC 客户端的登录缓存，先保存官服下发的数据快照，再将已适配的数据导入为一个**新的本地账号**。目前仅验证 PC 客户端协议版本 307；客户端或官服接口更新后可能需要适配。

1. 按 [切回官服](switch-official.md) 恢复官方客户端，亲自登录需要导入的账号，完成人工验证并进入已有角色，然后退出游戏。
2. 停止 Hoshimi 服务。客户端更新后先重新执行 `prepare`，确保运行文件与当前客户端匹配。
3. 在包含新版 `hoshimi.exe` 的目录打开 PowerShell 7，执行：

```powershell
.\hoshimi.exe import-official --account 'OfficialImport'
```

`OfficialImport` 是新建的**本地账号名**，可自行修改。命令使用 `config.json` 中的客户端路径和当前 Windows 用户的官服登录缓存，无需输入官服密码。仅当缓存有效时才能完成认证；收到验证或会话错误后，需回官方客户端重新登录。

有多个官服区服存在角色时，附加 `--official-server '1'` 指定区服 ID。使用其他数据目录时附加 `--home 'E:\Hoshimi'`；使用其他缓存目录时附加 `--prefs-dir '完整缓存目录'`。命令不会创建官服角色，也不会覆盖已有本地账号或存档；重试导入时应另选新账号名。

**成功标志：** 出现“官服导入完成”，并显示本地账号、UID、迁移数量、存档和快照路径，以及已接入、仅保存的指令数量。已接入指令表示其中有字段参与转换，不代表该指令的每个字段都能在本地生效。

当前接入范围：

- 管理员等级与累计经验、角色解锁及养成、永久皮肤、刻印及装备关系、钥从、货币、永久材料、个人资料和芯片。
- 剧情关卡的实际通关次数与星级、章节宝箱领取标记、任务进度及阶段与有效期、章节地图及剧情阅读标记、图鉴、编队。
- 签到日期、累计签到版本及领奖标记、七日签到、新手奖励、每日购买和体力领取记录；对策协议仅在官服与本地主题一致时接入。
- 已有存储结构支持的部分活动记录，包括音游成绩、赛车关卡及配装、弹珠、合成载具、自走棋、箱庭任务等；活动能否进入及具体规则仍以本地服务端实现为准。

限时库存不加入可用库存，其原始数量和有效期记录在存档的 `official_import.omitted_timed_items` 中。已过期任务不再下发，也不能领奖。当前登录逻辑会将昵称设为本地账号名；普通账号原有的入口解锁规则仍然适用，导入的剧情次数与星级则使用真实记录。

**原始快照位于 `data/official-snapshots/`。** 转换前逐帧保存非认证 protobuf 原文、可解码的 JSON、采集时间和运行文件协议身份，保留多帧与未知指令。初始化完成后额外查询普通、收藏邮件列表；不读取正文，不领取官服奖励。邮件列表及好友、公会等官服 UID 关联内容仅存档。

邮件查询未完成时，已取得的核心数据仍可导入，但结果说明会逐项提示缺失情况；读取结果同时保存在存档的 `official_import.additional_reads` 中。旧快照未记录读取结果时，也会提示无法确认邮件列表完整。

快照只包含本次登录和上述列表查询实际下发的数据，**不能保证取得所有官服内容**：隐藏数据、未下发的历史活动和官服内部状态可能缺失。尚未实现或尚未编写转换适配的数据只保存在快照中，不直接重放到客户端；这不代表对应玩法已经可用。命令不支持向官服写回。

已有快照可以离线重新转换，无需官服登录缓存：

```powershell
.\hoshimi.exe import-official --account 'OfficialRestored' --archive 'E:\Hoshimi\data\official-snapshots\你的快照.json'
```

离线导入要求运行文件的应用版本、协议哈希及资源清单哈希与快照匹配，并从原始 protobuf 重新解码，不采用快照中缓存的 JSON。请同时保留对应 `runtime` 和客户端资源。以后增加适配后，可使用同一快照、新的本地账号重新导入；目前不会自动将旧快照合并到已经游玩的账号。备份服务端时一并保留 `data`，其中的快照含个人游戏数据，不要公开上传。

4. 导入完成后，按 [首次使用第 4、5 步](quickstart.md#_4-启动服务端) 启动服务并切换本地服。用新建的本地账号登录，首次输入的密码会成为该账号的本地密码，请单独设置。
